# 产品概述

**状态：** 待验收  
**来源：** 同级 React Native 仓库 `money-app`（应用名 Moneyknows，当前版本 1.0.56）  
**用途：** 设计与实现的产品输入。未说开工前不写业务代码。

## 1. 产品是什么

Moneyknows 是面向美股的 **盘中交易辅助 App**：看实时行情、用扫描器找标的、在个股页看 K 线与关键价位，并通过用户自己的 Alpaca 账户下单、看持仓与订单。

它不是券商 App 的完整替代，也不是投顾。AI 解读只供参考，不构成投资建议。

一句话：

> 用原生 iOS 重建现有 Moneyknows：同一套账号与后端，把扫描、看图、订阅实时、下单走完。

## 2. 这次重构要达成什么

| 目标 | 说明 |
| --- | --- |
| 行为对等 | 受邀请用户在 RN 里能用的主路径，iOS 都要能用（**不含付费套餐**） |
| 后端不变 | 默认继续打 `money-api` / `money-gateway` 与 Alpaca；改接口必须先过需求提案 |
| 体验升级 | 原生导航、图表（蜡烛 / 线 / VWAP / 价格线 / 缩放）更稳，不再绑 RN K 线库 |
| 可演进 | 需求与设计分开；隐藏功能、Admin 功能、半残功能单独列出，不偷偷做进主路径 |

**本期不做 Android。** Android 继续用现有 RN。

## 3. 谁在用

| 角色 | 要完成的事 |
| --- | --- |
| 受邀请用户 | 用邀请码注册后登录；看仪表盘、扫股票、看详情图、订阅实时标的、配置 Alpaca 后交易。**没有付费档位，也不按套餐限权。** |
| 管理员（`role === admin`） | 第一期 App 内无专属入口。邀请码由运营线下发。本地存储调试、个股 AI View、个股价格通知、拉取全部订阅：后做 |

**准入只有邀请。** 邀请码由运营线下发放，App 内第一期不提供「邀请用户」。没有有效邀请码不能注册；没有账号不能登录。不做免费 / Pro、不做应用内购买、不做升级提示。现网目前没有真正的付费用户。

同一账号可以同时是交易者与管理员。产品不假设必须有社交关系。

## 4. 产品对象

用这些词，不要过早绑死实现类名。

| 对象 | 含义 |
| --- | --- |
| 账号 | 受邀请后用邮箱注册/登录的身份；可带角色。**不带付费套餐。** 一个应用账号将来可能绑定多个券商账户，见 [10-多券商账户.md](10-多券商账户.md) |
| 邀请码 | 注册的唯一门槛。运营线下发放；没有有效邀请码不能创建账号 |
| 券商账户 | 某个券商上的可交易账户。第一期只有一个本机 Alpaca（Key/Secret + 模拟/实盘）。不是服务端代持（现状） |
| 标的（symbol） | 美股代码，如 AAPL |
| 实时订阅 | 用户把自己关心的标的加入网关，才能收秒级行情并在交易 Tab 看到。这是行情订阅，**不是付费订阅** |
| K 线 | 日线 / 分钟线 / 秒线；可切蜡烛或折线 |
| 扫描器 | 后端算好的盘中排行/形态列表 |
| 订单 / 持仓 / 组合 | 来自 **当前券商账户**（第一期即那个 Alpaca），不是自家撮合 |
| 通知 | 服务端推送的盘中提醒（趋势、高低点、突破等） |

## 5. 参考实现，不是产品边界

`../money-app` 用来核对「今天已经做成了什么」。下列情况 **不能** 直接当成 iOS 必做：

- 菜单里注释掉的扫描器
- 入口被注释的微观分析
- 客户端直连 OpenAI / Gemini（密钥在本地或占位符）
- 仅 Admin 使用的调试页
- App Store / 套餐购买、免费 1 / Pro 5 的实时订阅限额（RN 有，**iOS 产品不做**）

这些都写在 [01-范围与分期.md](01-范围与分期.md)。已拍板项见 [08-待确认事项.md](08-待确认事项.md)。

## 6. 应用身份（已确认：直接替换现网 App）

做好后作为 **现有 App Store 应用的一次更新**，不是新应用。名称和 ID 必须与现在的 RN 包一致，否则无法覆盖安装、无法接同一套推送。

| 项 | 现网值 | iOS 必须 |
| --- | --- | --- |
| 展示名（主屏幕 / 商店） | `moneyknows` | 相同 |
| Bundle ID（生产） | `com.byteknows.moneyknows` | 相同 |
| 内部 PRODUCT_NAME | `moneyknows` | 相同 |
| 现网版本参考 | 1.0.56 | 上架版本号必须 **高于** 现网，具体数字设计/发版时定 |
| 推送 | 同一 Firebase iOS App（Bundle ID 同上） | 沿用现有 `GoogleService-Info.plist` / APNs |

本地调试可用现网已有的旁路 ID（不进商店替换）：`com.byteknows.moneyknows.dev`、`com.byteknows.moneyknows.staging`。

**覆盖安装不等于无感迁移。** RN 把会话和 Alpaca 凭证放在 MMKV 里，原生 App 默认读不到。第一期用户更新后需要重新登录并重填 Alpaca 凭证。若要无感带过登录态，另开需求，不在本期默认范围。

## 7. 已确认的客户端约束（非产品功能）

- 原生 iOS + SwiftUI
- 主图：Lightweight Charts；统计图：Swift Charts
- 不需要毫秒级刷新
- 中英文案（RN 已有 `zh` / `en`）
- 生产包名与展示名见第 6 节，不得另起 Bundle ID

## 8. 明确不是什么

- 第一期不是多券商交易终端（只做一个 Alpaca）。将来一个应用账号可绑 Alpaca / Schwab / IBKR 等，见 [10-多券商账户.md](10-多券商账户.md)；IBKR 在 RN 里目前只做筛选器与部分指数，不下单
- 不是完整 TradingView（不要画线工具、社区脚本、毫秒盘口）
- 不是投顾或自动跟单平台
- **不是付费订阅产品**（无 IAP、无套餐墙、无升级）
- **不是第三方登录产品**（无 Google、无 Apple，只有邮箱）
- **不是新上架的另一个 App**（必须覆盖现网 `com.byteknows.moneyknows`）
- 本期不是 Android 重写
