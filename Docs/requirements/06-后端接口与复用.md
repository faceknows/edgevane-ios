# 后端接口与复用

**状态：** 待验收  
**原则：** 默认不改后端。下面「现有接口」是 iOS 要对接的合同；「提案」默认不采纳，除非你在 [08-待确认事项.md](08-待确认事项.md) 勾选。

## 1. 主机（现状，三套 env URL 相同）

| 用途 | 地址 |
| --- | --- |
| REST | `https://money-api.byteknows.com` |
| Socket.IO + 订阅 REST | `https://money-gateway.byteknows.com` |
| Alpaca 交易 | `https://paper-api.alpaca.markets` 或 `https://api.alpaca.markets`（用户选） |
| Alpaca 行情 REST（少数直连） | `https://data.alpaca.markets` |
| Alpaca 交易 Socket | `wss://paper-api.alpaca.markets/stream` 或 live 对应地址 |

公共请求头：

- `Authorization: Bearer <accessToken>`（需登录的接口）
- `X-App-Version`
- `X-Platform: ios`

版本过低：HTTP 426 或 `errorCode: APP_VERSION_NOT_SUPPORTED`。

## 2. 账号

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/users/email/signup` | 注册，需邀请码 |

| POST | `/v1/users/email/verification-code` | 只用于忘记密码（`reset-password`）。注册不发码 |

| DELETE | `/v1/users/me` | 删号 |

**iOS 不根据 `subscription` / 套餐做任何产品行为**（不限权、不展示、不引导购买）。

## 6. 实时订阅（网关主机）

| 方法 | 路径 |
| --- | --- |
| GET | `/alpaca/market/subscriptions` → `{ all, me }` |
| POST | `/alpaca/market/subscribe` `{ symbols }` |
| POST | `/alpaca/market/unsubscribe` `{ symbols }` |

Socket.IO：

- `{SOCKET_HOST}/alpaca-stream`，JWT 放 auth/query
- `{SOCKET_HOST}/ibkr-stream`（新闻、指数相关）

Alpaca 流里第一期要消费：

| 事件 | 用途 |
| --- | --- |
| `trade` | 已订阅代码最新价 |
| `quote` | 已订阅盘口 bid/ask（`bp` / `ap`）。**必须消费**；REST 快照兜底 |
| `second-trade` | 秒图 |
| `news` | 新闻列表 + 可选 toast |
| `trade_updates` | 订单变化、触发自动止盈止损 |
| `ping` | 心跳 |

可忽略：`bar`、`micro_analysis_minute_complete`。

## 9. 后端提案（默认全部不采纳）

仅在你明确要改后端时才进入设计。

1. **订单推送只留一条。** 现在网关 + Alpaca 直连都会推 `trade_updates`，容易重复提示。可保留直连、网关只推市场；或反过来由网关扇出。
2. **订阅 REST 与业务 REST 分属两台主机。** iOS 要配两套 Base URL。可把订阅接口归到 `money-api`，网关只留 Socket。体验不变。
3. **环境分离。** 开发/预发/生产 URL 现在一样。TestFlight 若要隔离，需要真正的 staging。
4. **分钟线增量。** 现在每分钟拉全量。若网关 `bar` 事件补全，详情页可少打 REST。属优化，不是功能。
5. **打开微观分析实时事件。** 若第二期做微观分析，应恢复 `micro_analysis_minute_complete`，避免只靠 REST。
6. **交易计划 AI 改服务端。** 不要在 iOS 存 OpenAI/Gemini Key。新增例如 `POST /v1/ai/trade-execution-plan` 后再做该功能。
7. **凭证上云。** 换机要重填 Alpaca Key。可选后端保险库。涉及安全与合规，不建议第一期。
8. **统一响应信封与分页。** 部分接口直接返回数组，部分包 `{ data }`。属客户端可消化的脏合同，不挡第一期。
9. **Socket 握手带版本。** 与 HTTP 的 `X-App-Version` 对齐，便于踢旧客户端。优化项。

第一期客户端应 **兼容现状的两种响应形状和双主机**，而不是等后端先改。
