# 多券商账户（设计预留，第一期不实现）

**状态：** 已确认方向  
**实现：** **不做。** 只约束阶段 B 的设计，避免把「一个 App 账号 = 唯一 Alpaca」写死。

## 1. 产品意图

一个 Moneyknows **应用账号**，将来可能绑定 **多个券商账户**，例如：

- Alpaca（已有）
- Charles Schwab
- IBKR（Interactive Brokers）
- 以及以后其它券商

绑定、切换、同时看多个账户的持仓，都是以后的事。第一期用户感知与现在 RN 相同：只配 **一个** Alpaca（模拟或实盘），只在这一个账户上交易。

## 2. 两个对象必须分开

| 对象 | 含义 | 第一期 |
| --- | --- | --- |
| 应用账号 | 邀请码 + 邮箱登录的身份 | 做 |
| 券商账户 | 某个券商上的可交易账户（凭证、环境、持仓、订单、资金） | 只做 1 个 Alpaca，界面不必出现「券商」二字 |

订单、持仓、组合、下单、自动止盈止损，在概念上属于 **当前券商账户**，不属于「这个邮箱的人」本身。

行情扫描、分钟 K 线、通知可以仍走现有后端，不绑死「必须来自当前券商」。IBKR 在 RN 里已用于筛选器/指数，那是行情来源，不是已绑定的交易账户。

## 3. 第一期做什么 / 不做什么

**做（与现在一致）：**

- 设置里填一组 Alpaca Key / Secret，选模拟或实盘
- 持仓、订单、组合、下单都针对这一组凭证
- 仪表盘今日盈亏卡片标明模拟 / 实盘
- 下单弹窗（含滑条）标明模拟 / 实盘，因确认即提交

**不做：**

- 绑定第二个 Alpaca 或其它券商
- 账户列表、切换当前账户
- Schwab / IBKR 交易或 OAuth
- 把凭证改传到 Moneyknows 后端（现状仍本机存放）
- 为「将来」先做空的「添加券商」按钮

## 4. 设计必须留下的口子

阶段 B 必须做到（实现可以只接 Alpaca）：

1. **领域模型有「券商账户 / 连接」这一层**，不要把 Key 直接当成用户属性散落在各个页面。
2. 下单、拉持仓、拉订单、自动止盈止损都走「当前券商账户」这一个入口。第一期全局只有一个当前账户。
3. 新增一种券商时，应主要加一种连接实现，而不是复制交易页、持仓页、订单页。
4. 凭证存储按「账户」隔离，不要写成全局唯一的 `alpacaKey` 常量到处读。
5. 页面文案可以写 Alpaca（因为第一期只有它），但交易领域不要出现「只能是 Alpaca」的死分支洒在 UI 里。

不要求现在设计 Schwab/IBKR 的具体 API。不要求改后端。等真做多券商时再开需求（含：凭证是否上云、OAuth、多账户资金展示）。
