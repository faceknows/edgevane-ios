# 工程与扩展原则

**状态：** 已验收
**性质：** 非功能需求。约束后面的设计和实现，不规定文件夹或类名。  
**详细落地**（模块怎么切、图表怎么包）等阶段 B 写进 `Docs/design/`。

原生重写不是把 RN 页面逐个抄进 SwiftUI。第一期功能可以少，结构必须能长。

## 1. 要解决什么

这个 App 会继续加扫描器、周期、价格线、交易动作。如果详情页、图表、下单、接口调用缠在一起，每加一个开关就要改一整页。

因此设计和实现必须满足：

- **可扩展**：加一种扫描器、一种 K 线周期、一条价格线、一种订单动作，应主要是加，而不是改核心页。
- **可复用**：同一块 UI 或同一套数据转换，只实现一次。
- **可替换**：图表库、HTTP 客户端、推送实现可以换，业务页面不重写。
- **可测**：计算（VWAP、数量、开盘保护）不依赖界面。

## 2. 分层（产品语言）

至少分清四层，页面不得直接打 URL、不得直接操作图表库 API。

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 页面 | 导航、布局、把用户动作交给领域 | 拼请求、算 VWAP、调 Alpaca 路径 |
| 领域 | 会话、行情订阅、下单规则、偏好 | SwiftUI 控件、具体图表库 |
| 图表 | 把「棒 + 线 + 价格线」画出来，处理缩放/十字光标 | 拉接口、算指标、知道用户有没有订阅 |
| 集成 | HTTP、Socket、Keychain、推送、StoreKit（若以后有） | 业务文案、页面结构 |

RN 参考实现可以对照行为，**不要**按它的 store/hook 文件一一映射成 iOS 类型。

## 3. 图表

对应 [05-图表.md](05-图表.md)。工程上必须：

1. **一个主图能力，多处使用。** 详情分钟图、盘前盘后、历史分钟页，走同一套「K 线表面」。日线、秒线可以是同一表面的不同数据，而不是三套互不相干的库封装。
2. **图表只吃数据。** 输入是棒（OHLCV + 时间）、叠加折线（如 VWAP）、价格线、**买卖点标记**、形态（蜡烛/折线）。输出是用户手势（缩放、选中某根或某个标记）。
3. **VWAP、均线、RSI/ADX/ATR 在图表外算。** 图表库当画笔，不当指标引擎。
4. **统计图不要塞进交易主图。** 盈亏数字卡、订阅监视 / 扫描器迷你图走另一套轻量图画法，不嵌 K 线表面；迷你图自带时间轴、价格轴、高低/现价。
5. 以后若换掉 Lightweight Charts，应只动图表层，详情页与历史页不重写。

验收（设计阶段就要对齐）：新增「成本价」价格线，只需多传一条线，不必改图表内部手势或缩放。

## 4. 组件复用

下列东西在两个以上页面出现时，必须是共用能力，禁止复制一份再改：

| 能力 | 会出现的地方 |
| --- | --- |
| 空态 / 加载 / 失败可重试 | 列表、图表、情绪、通知 |
| 股票行（代码、价格、涨跌幅、成交量同一行，点进详情） | 扫描器、持仓、搜索、通知 chips |
| 分钟迷你图 | 交易 Tab（折线）、扫描器结果（共用 `SparklineView`；扫描器画蜡烛 + 蓝色 VWAP，无秒图）。都有时间轴、价格轴、最高/最低/当前价。分钟数据与详情共用同一份当日 1 分钟棒；同一分钟同一代码不重复请求（含无行情空结果）。扫描器空棒走可配置空态；交易 Tab 空数据留空 |
| 订阅监视卡片（价 + 分钟/秒迷你折线） | 交易 Tab；迷你折线不嵌交易主图 |
| 交易确认（价格、数量、环境：模拟/实盘） | 交易条、滑条下单、平仓 |
| 涨跌 / 今日盈亏 / 指标数字徽标 | 仪表盘、详情 |
| 分段切换（1M/3M/5M、蜡烛/线） | 详情、秒图 |
| 扫描器可点选项（方向、周期、最低价、最低量、K 线数量） | 动量、ATR、价格斜率及其它扫描器筛选 |
| 中英文案 | 所有用户可见文字 |

新增扫描器：应复用「拉列表 → 股票行 → 进详情」，只换数据来源和筛选，不新做一整页表格。

## 5. 可扩展的具体含义

第一期不必实现下列能力，但设计不得堵死：

| 以后可能加 | 现在不能做成 |
| --- | --- |
| 隐藏扫描器重新打开 | 扫描器目录写死在一个巨大 switch，加一项要改导航核心 |
| 微观分析、副图（RSI 曲线） | 图表组件写死「只有主图 + VWAP」，没有叠加层/副图扩展点 |
| 复盘（选日 + 当天买卖点） | 图表没有一等的 `markers`；为复盘再写一套绘图。必须与详情共用 `ChartSurface` |
| 更多价格线（止盈、提醒价） | 价格线写死昨收/今开两个常量 |
| 新周期（15 分钟等） | 周期枚举散落在页面字面量里 |
| Admin 入口 | 权限判断复制到每个按钮 |
| 无感迁移 RN 登录态 | 会话存储没有单一入口（Keychain 乱写） |
| 将来再谈付费 | 页面里不要预埋套餐墙；限额若有，走角色/配置，不写死 Pro |
| 一个应用账号绑定多个券商（Alpaca / Schwab / IBKR…） | 见 [10-多券商账户.md](10-多券商账户.md)。交易/持仓/订单不要写成「用户身上唯一的 Alpaca Key」。第一期不实现、不预埋「添加券商」按钮 |

**允许** 第一期少做功能。**不允许** 第一期把结构做成只能复制粘贴才能加功能。

## 6. 文案、主题、错误

- 用户可见字符串走中英资源，不在页面里写死中文或英文（调试日志除外）。
- 深色/浅色跟系统或设置走，颜色不写死在业务页。
- 失败要可重试、原因可读。网络、凭证、开盘保护、Alpaca 拒单，各有明确说法，不要统一「出错了」。

## 7. 安全与身份

- 会话和 Alpaca 密钥只走本机安全存储，不进日志、不进截屏调试页（Admin 调试另论，且第一期不做）。
- 生产 Bundle ID / 展示名见 [00-概述.md](00-概述.md) 第 6 节。
- 集成层集中带 `Authorization`、`X-App-Version`、`X-Platform`，页面不拼 header。

## 8. 实现时禁止

- 在 `SymbolDetail` 一类大页里直接 `URLSession` + 图表库 API + 下单。
- 为每个扫描器复制一套列表 UI。
- 把付费、Google 登录「先留个空按钮」。
- 为了赶进度把 VWAP 算进图表库配置，导致历史页再写一遍。
- 发明新的后端路径。现有合同见 [06-后端接口与复用.md](06-后端接口与复用.md)。

## 9. 和阶段 B 的分工

本文只回答「必须具备哪些工程性质」。阶段 B 的设计必须逐条落到：

- 模块边界与依赖方向
- 图表输入/输出模型
- 共用 UI 清单
- 会话与密钥存放
- 和现有 API 的映射

设计若违反本篇，先改设计，不要在实现里例外。
